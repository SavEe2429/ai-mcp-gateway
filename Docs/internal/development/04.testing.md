# 04. Testing & Quality Verification

## Hermetic Test Environment

`tests/__init__.py` configures `GATEWAY_DATA_DIR`, `GATEWAY_DB_PATH`, `GATEWAY_WORKSPACE_DIR`,
and `GATEWAY_CLIENT_SECRET_FILE` inside an ephemeral temporary directory before importing
`ai_mcp_gateway.main`. Test runs never mutate or read your local `data/gateway.db`,
`data/gateway.lock`, or `workspace/`.

## Quality Gate Commands

```bash
# 1. Static analysis & import sorting
uv run ruff check src/ tests/ packaging/ templates/ .github/scripts/release/
uv run ruff format --check src/ tests/ packaging/ templates/ .github/scripts/release/

# 2. Full unit + integration test suite
uv run pytest

# 3. Standard unittest runner
uv run python -m unittest discover tests

# 4. Lockfile consistency check
uv lock --check

# 5. Secret leak scan (Gitleaks)
gitleaks git --redact -v --no-banner .
```

## CI Parity

`.github/workflows/ci.yml` executes the exact same verification tiers (including the SHA-256
verified Gitleaks git scan) on every push and pull request targeting `main` or `master`.

## Optional Local Markdown & Docs Checks

When editing documentation or config files, verify against `.markdownlint.yaml`, `.prettierrc.yaml`,
and `mkdocs.yml` (see [`01.getting_started.md`](01.getting_started.md) for installation):

```bash
npx markdownlint-cli2 "Docs/**/*.md" "README.md" "CHANGELOG.md" "CONTRIBUTING.md" "SECURITY.md"
npx prettier --ignore-path .gitignore --check "**/*.{md,yaml,yml,json}"
uvx --with mkdocs-material mkdocs build --strict
```
