# 06. Troubleshooting

## Common Issues

### 1. Tailscale Funnel Fails to Start

- **Symptom**: Console prints `[Tailscale] Unable to query status` or `DNSName unavailable`.
- **Resolution**: Ensure the Tailscale desktop client is signed in and MagicDNS + Funnel are enabled
  on your tailnet. For local-only testing, set `server.enable_tailscale_funnel: false` in
  `config/config.yaml`.

### 2. Dashboard Returns `403 Forbidden`

- **Symptom**: Accessing `/ui` or `/api/ui/state` returns `403`.
- **Resolution**: The dashboard is intentionally locked to localhost (`127.0.0.1`, `::1`). Do not
  access `/ui` through the public Tailscale Funnel URL or external reverse-proxy `X-Forwarded-*`
  headers.

### 3. `.exe` Fails to Persist Database or Workspace

- **Symptom**: State resets on restart.
- **Resolution**: Place `ai-mcp-gateway.exe` in a writable directory (not a read-only folder such as
  `Program Files`). Verify `data/gateway.db` and `workspace/` are created beside the executable.

### 4. Commit Rejected by `commit-msg` Hook

- **Symptom**: `pre-commit` rejects a commit message.
- **Resolution**: Prefix commit subjects with an allowed Conventional Commit type (`feat`, `fix`,
  `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`).

### 5. `AI Agent MCP Gateway is ALREADY RUNNING!`

- **Symptom**: Launching a second copy exits immediately with code `1` and displays the active PID
  and `data/gateway.lock` path.
- **Resolution**: Only one gateway instance may run against the same `data/` directory at a time.
  Use the running dashboard (`http://localhost:3000/ui`) or close the existing instance before
  restarting. (If a previous process crashed, the OS automatically releases the lock; re-launching
  reuses or replaces the stale file.)

### 6. Pre-Commit Fails on `gitleaks-system`

- **Symptom**: `pre-commit` reports `gitleaks: command not found` or flags a staged secret.
- **Resolution**: Install `gitleaks` (`v8.30.1+`) in your `PATH` (for example
  `winget install --id Gitleaks.Gitleaks -e` on Windows). If Gitleaks flags a real secret, remove
  it from the staged diff before committing; for verified test fixtures, keep them under ignored
  paths or use explicit `gitleaks:allow` only when safe.
